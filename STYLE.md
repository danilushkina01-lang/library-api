# STYLE.md — Правила оформления API

1. **Именование путей**: Все пути начинаются с `/v1`. Ресурсы во множественном числе: `/books`, `/readers`, `/loans`.
2. **HTTP-методы**: Используем стандартные методы REST: GET, POST, PUT, DELETE.
3. **Пагинация**: Для всех списков обязательны `page` (по умолчанию 0) и `size` (по умолчанию 20, максимум 100). Ответ содержит `items` и `total`.
4. **Фильтрация и сортировка**: Фильтры передаются как query-параметры. Сортировка — параметр `sort`.
5. **Ошибки**: Все ошибки возвращаются в едином формате `ErrorResponse` с кодами: `INVALID_REQUEST`, `NOT_FOUND`, `VALIDATION_ERROR`, `CONFLICT`, `BUSINESS_RULE_VIOLATION`, `IDEMPOTENCY_MISMATCH`.
6. **Авторизация**: Все мутации требуют Bearer JWT в заголовке `Authorization`.
7. **Идемпотентность**: POST-запросы (особенно `/loans`) должны содержать заголовок `Idempotency-Key` (UUID).
8. **Даты и время**: Все даты в формате ISO 8601 (`YYYY-MM-DDThh:mm:ssZ`).
9. **Идентификаторы**: Все ID — UUID v4.
10. **Примеры**: Для каждой операции должно быть минимум 3 примера запросов/ответов.
11. **Устаревание полей**: Все устаревшие поля помечаются флагом `deprecated: true` в схеме. В описании операции должно быть пояснение, чем его заменить (или что логика теперь на стороне сервера).
